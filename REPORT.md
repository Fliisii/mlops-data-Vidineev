## 4. Сравнение подходов

| Критерий | DVC | ClearML Dataset |
|---|---|---|
| Идентификатор версии | Git-коммит и метаданные `.dvc` с хешем содержимого | ID датасета и номер версии |
| Хранение данных | В DVC cache и настроенном remote | В хранилище ClearML |
| Связь с Git | Тесная: метаданные DVC отслеживаются в Git | Связь через метаданные, ID и историю экспериментов |
| Наследование версий | Состояние данных восстанавливается по метаданным выбранного коммита | Можно явно указать родительский датасет |
| Основные сценарии использования | Воспроизводимые ML-пайплайны, контроль данных и артефактов в Git-ориентированном процессе | Управление датасетами и их версиями в экосистеме ClearML |

## 5. Ответы на контрольные вопросы

### 1. Что идентифицирует версию данных?

Версия данных описывает конкретное состояние набора файлов. Для воспроизводимости важны идентификатор версии, состав файлов и их содержимое. Хеши позволяют проверить, совпадают ли восстановленные файлы с ожидаемыми.

### 2. Почему одного Git-коммита недостаточно без удалённого хранилища данных?

Git хранит коммит и метаданные DVC, но сами большие данные могут находиться в DVC cache и remote. Если удалённое хранилище недоступно или необходимые объекты не были отправлены, одного клона Git может оказаться недостаточно для восстановления датасета. Поэтому после клонирования выполняют `dvc pull`.

### 3. Чем версия ClearML Dataset отличается от ID датасета?

ID — уникальный идентификатор конкретного объекта датасета в ClearML. Номер версии, например `1.1.0`, — человекочитаемое обозначение состояния в истории датасетов. В этой работе каждой версии соответствует собственный ID.

### 4. Почему `finalize()` не создаёт следующую версию автоматически?

`finalize()` завершает подготовку текущего объекта датасета и фиксирует его состояние. Для создания следующей версии нужно явно создать новый объект датасета, указать номер версии и при необходимости родительский датасет.

### 5. Как доказать, что версия 2.0.0 основана именно на базовой версии?

Нужно проверить метаданные родителя в ClearML. В данной работе `_get_parents()` вернул ID базовой версии `6ac33e7c1410404f91d8b5fb274bef2d`. Дополнительно сравнивают состав файлов и хеши: в `2.0.0` есть только изменённый Iris, а Wine отсутствует.

### 6. Что произойдёт при `git switch`, если не выполнить `dvc checkout`?

Git переключит версии файлов, которые он отслеживает, включая метаданные `.dvc`, но рабочие данные могут остаться в состоянии предыдущей версии. `dvc checkout` синхронизирует файлы данных с метаданными выбранного коммита, используя локальный cache. Если нужных объектов нет в cache, потребуется `dvc pull`.

### 7. Когда предпочтительнее DVC, а когда ClearML Dataset?

DVC удобен, когда требуется связывать состояние данных с Git-коммитами, воспроизводить ML-пайплайны и хранить большие файлы отдельно от исходного кода. ClearML Dataset полезен, когда требуется управлять версиями датасетов, задавать родительские версии и работать с ними в экосистеме ClearML. Инструменты можно использовать совместно, если это соответствует архитектуре проекта.
